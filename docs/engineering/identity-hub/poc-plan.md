PRD 17.5 rejects a POC that only shows a successful login. A passed scenario needs a product version, the configuration used, the steps, logs, API results, the data left behind, and the limits. This pass has none of that live evidence. No scenario is PASS. No scenario is FAIL, because nothing was executed far enough to fail an assertion. Status is NOT RUN, BLOCKED, or N/A.

This pass did not modify production, and it did not modify the Casdoor test instance. Read-only calls against that instance were skipped. A safe read still needs a credential and a confirmed non-production host, and this pass did not establish either from repository config without handling secrets. Source inspection of `@nocobase/app-plugin-casdoor-identity` is cited where it explains a gap. Source inspection is not a POC pass.

## What would count as a pass later

Each rerun records the product name and version, the issuer URL (without secrets), the client id, the steps, the HTTP or log excerpts, and the resulting `personId`, `identityKey`, and membership row. Secrets, passwords, authorization codes, and access tokens stay out of the record. A Casdoor read-only follow-up may collect the discovery document and the product version only. It still does not pass POC-06 until the same Person is resolved in the Hub and in at least the intended app projection. Keycloak, Authentik, LDAP, and a second OIDC provider stay BLOCKED until those systems exist in an environment this project is allowed to use.

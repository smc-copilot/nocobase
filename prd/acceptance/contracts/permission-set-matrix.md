# Permission Set matrix (PRD §5.1)

These are recommended Permission Set combinations for Control and managed Apps. They do not introduce a parallel authorization system; grants are expressed with native Authorization resources (`rel.*` business actions, `rel.environments` settings, and App settings items). Exact set names are application-owned; this matrix freezes the intended capability boundaries.

| Role                      | `rel.apps/*` business actions                                                                                                          | `rel.environments/*` settings                            | Other settings / notes                                                                                                                                                                                                   |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Platform administrator    | `view`, `read-logs`, `create`, `configure`, `upload`, `deploy`, `deploy-protected`, `operate`, `delete` (all Apps)                     | `read`, `manage`                                         | Full control-plane Host, repository, configuration, and integration settings. Does **not** automatically receive every managed App’s business-document permissions.                                                      |
| Release operator          | `view`, `read-logs`, `upload`, `deploy`, `operate` on assigned Apps; no global `create`/`configure`/`delete` unless explicitly granted | `read` only                                              | May upload, publish, start/stop, and read logs for nominated Apps. No global user-mapping admin; no Secret plaintext read.                                                                                               |
| Identity administrator    | none by default                                                                                                                        | none by default                                          | IdP configuration, `externalIdentities` / mapping / sync settings, disable handling. No deploy or document-operation grants by default.                                                                                  |
| Integration administrator | `view` on assigned integration demo Apps only when needed for diagnosis                                                                | `read` when needed for connection environment visibility | Octop connection registry, subject bindings, form registration settings. Must not use connection service secrets to access user documents.                                                                               |
| Auditor                   | `view`, `read-logs` (read-only) on Apps in scope                                                                                       | `read`                                                   | Desensitized deployment, identity, operation, and security-event read access. No write, ticket redeem, or token/Secret plaintext.                                                                                        |
| Generic test user         | none on `rel.*`                                                                                                                        | none                                                     | Only authorized operations on own test documents via Business UI Adapter / form handlers. No platform management. Negative authorization tests use the same user under different Permission Sets, not a second identity. |
| CI service account        | scoped API key: typically `view`, `upload`, `deploy`, `operate` on nominated Apps; never `configure`, `deploy-protected`, or `delete`  | no `rel.environments/*`                                  | Restricted API Key only. No interactive login, no cross-App root, no identity-mapping admin.                                                                                                                             |

## Resource key reference

- Business actions: `rel.apps/view`, `rel.apps/read-logs`, `rel.apps/create`, `rel.apps/configure`, `rel.apps/upload`, `rel.apps/deploy`, `rel.apps/deploy-protected`, `rel.apps/operate`, `rel.apps/delete`.
- Settings: `rel.environments/read`, `rel.environments/manage`.
- Identity and Business UI administration surface as Authorization settings items owned by `app-plugin-casdoor-identity` and `app-plugin-business-ui-adapter` (registered in later phases); this matrix only records which roles may receive those settings grants.

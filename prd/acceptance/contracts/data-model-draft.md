# Conceptual data model draft (PRD §11.1)

Conceptual collections and uniqueness constraints for the SMC platform foundation. Physical table names may gain repository prefixes; this draft does not replace immutable migrations. Control App release/environment/deployment data reuse native Releases models and are not duplicated here.

| Collection                     | Key fields                                                                                  | Uniqueness / constraints                                                                   | Purpose                                                |
| ------------------------------ | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------ |
| `identityProviders`            | `providerId`, `issuer`, `clientId`, `secretRef`, `claimMapping`, `admissionPolicy`          | `providerId` unique per App; secrets never echoed in plaintext                             | Trusted IdP configuration for the App                  |
| `externalIdentities`           | `providerIssuer`, `providerSubject`, `localUserId`, `lastSyncedAt`                          | Unique `(providerIssuer, providerSubject)`; does not alter native auth tables              | Maps verified external subject to local user           |
| `managedPermissionAssignments` | `localUserId`, `mappingRuleId`, `permissionSetId`, `sourceRevision`                         | Unique assignment per user+rule+set as implemented; adapter may revoke only its own grants | Tracks Permission Sets granted by the identity adapter |
| `identitySyncRuns`             | `batchId`, `cursor`, `counts`, `result`, `errorClass`                                       | `batchId` unique                                                                           | Sync batch audit and restart cursor                    |
| `businessUiConnections`        | `connectionId`, `octopIssuer`, `allowedOrigins`, `serviceSecretHash`/`secretRef`, `enabled` | `connectionId` unique; credentials per connection, not shared across instances             | Octop connection registry                              |
| `businessUiSubjectBindings`    | `connectionId`, `octopSubject`, `localUserId`, `externalIdentityId`, `status`               | Unique `(connectionId, octopSubject)`; changes audited                                     | Controlled Octop subject pre-binding                   |
| `businessUiForms`              | `formRef`, `schemaVersion`, `mode`, `handlerKey`, `permissionRef`                           | Unique `(formRef, schemaVersion)` per App                                                  | Form registration whitelist                            |
| `businessUiOAuthCodes`         | `stateDigest`, `connectionId`, `encryptedCode`, `expiresAt`, `consumedAt`                   | `stateDigest` unique; short-lived, single-use; no plaintext verifier                       | OAuth authorization code handoff                       |
| `businessUiTickets`            | `ticketDigest`, `subjectBindingId`, `context`, `expiresAt`, `consumedAt`                    | `ticketDigest` unique; atomic consume; replay rejected                                     | Embed tickets                                          |
| `businessUiEmbedContexts`      | `authSessionRef`, `interactionId`, `formRef`, `actionBounds`, `expiresAt`                   | Bound to native session; cannot authenticate alone                                         | Server-side embed session context                      |
| `businessUiInteractions`       | `interactionId`, `connectionId`, `subjectBindingId`, `recordId`, `latestReceiptId`          | `interactionId` unique; subject/ownership not client-rewritable                            | Interaction ledger                                     |
| `businessUiOperations`         | `operationId`, `interactionId`, `idempotencyKey`, `requestDigest`, `status`, `result`       | Unique idempotency key in scope; query does not submit                                     | Operation ledger                                       |
| `businessUiReceipts`           | `operationId`, `interactionId`, `recordVersion`, `sequence`, `payload`                      | Immutable snapshots; sequence monotonic per interaction                                    | Authoritative receipts                                 |
| `integrationTestDocuments`     | `draftId`, `formalRecordId`, `ownerId`, `title`, `quantity`, `status`, `version`, `batchId` | Formal id assigned in submit transaction; test App only                                    | Generic verification documents                         |

P0 implements only `externalIdentities` as a physical migration; remaining collections land with identity and Business UI Adapter phases.

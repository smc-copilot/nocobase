# Meeting domain (this application)

This application is a product App under `packages/apps/app-meeting`, not a create-app template. It was started from `@nocobase/app-template-default` (`nocobase.templatePackage`) and keeps native Auth, Users, Authorization, files, secrets and the application shell. Meeting records, access rows, connections, query runs, content, OA drafts, operations, pages, routes, services and migrations stay in this application. Do not move the meeting domain into `packages/plugins`, `app-server`, default, examples, Control or Integration Demo.

B0 is the runnable shell: sign-in, users and roles, a `/meetings` page, and `GET /api/meetings` filtered by `meeting.granted` record access through `withPolicy`. Page `meetings/access` and action `meeting/read` are separate grants. `meeting-operator` has both; `accounts-manager` has neither. Do not seed either set onto `authenticated:*`, `member`, or every signed-in user. Root remains the platform unrestricted administrator; a user who only has account-management grants must not read meetings.

B1 is gateway binding: System settings page `meeting-connections`, OAuth start/callback with single-use state bound to the current local user, origin allowlist, and native Secrets sealing. Tokens never appear in API or audit payloads. Disconnect stops this application's later gateway access immediately. Upstream revoke is not implemented; say so, do not pretend. Admins do not automatically receive other users' bindings. Live OAuth start without a published identity-token contract throws `GATEWAY_IDENTITY_TOKEN_UNAVAILABLE`. `meetingGateway.testAdapter` and `MEETING_GATEWAY_TEST_ADAPTER` exist only for isolation tests.

B2 is explicit query and stored details: `POST /api/meeting-query-runs` writes a durable QueryRun ledger, then the same request executes the gateway query. Page load does not auto-sync. Source uniqueness is `gateway_instance + org_id + connection_ref + upstream_meeting_id + source_cycle_id`. `meeting_code` is display-only and must not merge rows across connections. Query failure keeps known meetings. `GET /api/meetings/{meetingId}` and its participants/recordings routes return stored rows; missing fields stay `not_provided` / `not_fetched`, never zero or success. Recording URLs are minted on authorized download and are not stored as long-lived signed links. This batch does not fetch arbitrary URLs.

B3 is local content: durable import runs keyed by stored `recordFileId`, never a client download URL. `meeting_summary` is original dialogue and `ai_meeting_transcripts` is optimized. The public content DTO exposes raw `tencentMinutes` and `tencentDialogues`; projection minutes never replace those originals. Multiple files in one group are concatenated in import order. Re-import updates source text and does not overwrite local edits. Historical reverse mapping is repaired only with provenance evidence. Tencent to-dos extracted from whitelist headings (including 会议待办) are source facts, not assigned OA tasks. HTTP import lists record-file details then downloads the signed HTTPS URL without forwarding gateway tokens. Isolation `testAdapter.importRecordingContent` is labeled test-adapter and uses distinct ORIGINAL_ONLY / OPTIMIZED_ONLY markers.

B4 is the OA workspace. `/meetings/:id` replace-redirects to `/oa`. `/summary` is the read-only Tencent source page (four minutes tabs plus always-visible original/optimized dialogues), not a Tencent website URL. `/oa` is the shared workspace: no duplicate page shell and no second draft store. Drafts keep version/CAS, stable `clientTaskId`, person chips, the seven-column task table, and the full meeting/minutes field set. Save draft is zero OA writes. Current identity is determined on the server; missing mapping still allows a valid draft and blocks formal sync with `OA_MAPPING_MISSING`. Controlled delegation is an explicit row. Restricted supplemental files are meeting-owned (`supplement` action), not a generic attachment platform. Secrets use native seal/open and are never echoed. Root is not a default employee.

B5 is the execution ledger: `meetingOaOperations` + steps + per-`clientTaskId` results + outbox lease (`leaseVersion` CAS, not a process lock). Pre-sync checks local account, meeting grant, `oaSync`, trusted creator/delegate, and draft fields, then freezes creator/payload in one transaction. Same `requestId` returns the original operation; a new `requestId` cannot open a second create intent for the same meeting + OA target. Writes run `createMeeting` → `uploadSummary` → `createTaskByMeeting`. The upload step stores the real `summaryId` from the OA response, never the meeting id. Timeout/lost response/`in_flight` crash is UNKNOWN and is not resent. GET is a pure read. Unmatched task results are not filled by name-position. Reconcile (`oaReconcile`) records evidence only. Recover (`oaResume`) is a separate execution-page command that keeps the frozen intent and continues only after `not_sent` evidence; the reconciler set does not include `oaResume`.

Do not call Agent, AnythingLLM, Casdoor, RAG, or a generic designer from this application. The HTTP adapter implements token (Basic, form+query) and the three writes from the 16d1f2762a9eddd5cf395b2f7a3e4d9d40d8318a OA helpers when `meetingUrl`, client id and secret are configured. Local HTTP contract tests prove request shape; they are not live OA or gateway captures. `writeContract`/`tokenContract` may be `configured` after settings exist; `liveVerified` stays false until an authorized live environment is proven. People search HTTP follows `oaPeople.js` (`GET peopleUrl?fd_name=`), reading `meetingOaSettings.peopleUrl` at call time then env. Saving URLs without a new secret must not increment `credentialVersion`, because native open AAD is `[id, credentialVersion]`. `meetingOa.testAdapter` is isolation-only and must be labeled “本地测试数据，未调用真实OA” in the UI.

# Meeting domain (this application)

This application is a product App under `packages/apps/app-meeting`, not a create-app template. It was started from `@nocobase/app-template-default` (`nocobase.templatePackage`) and keeps native Auth, Users, Authorization, files, secrets and the application shell. Meeting records, access rows, connections, query runs, content, OA drafts, operations, pages, routes, services and migrations stay in this application. Do not move the meeting domain into `packages/plugins`, `app-server`, default, examples, Control or Integration Demo.

B0 is the runnable shell: sign-in, users and roles, a `/meetings` page, and `GET /api/meetings` filtered by `meeting.granted` record access through `withPolicy`. Page `meetings/access` and action `meeting/read` are separate grants. `meeting-operator` has both; `accounts-manager` has neither. Do not seed either set onto `authenticated:*`, `member`, or every signed-in user. Root remains the platform unrestricted administrator; a user who only has account-management grants must not read meetings.

B1 is gateway binding: System settings page `meeting-connections`, OAuth start/callback with single-use state bound to the current local user, origin allowlist, and native Secrets sealing. Tokens never appear in API or audit payloads. Disconnect stops this application's later gateway access immediately. Upstream revoke is not implemented; say so, do not pretend. Admins do not automatically receive other users' bindings. Live OAuth start without a published identity-token contract throws `GATEWAY_IDENTITY_TOKEN_UNAVAILABLE`. `meetingGateway.testAdapter` and `MEETING_GATEWAY_TEST_ADAPTER` exist only for isolation tests.

B2 is explicit query and stored details: `POST /api/meeting-query-runs` writes a durable QueryRun ledger, then the same request executes the gateway query. Page load does not auto-sync. Source uniqueness is `gateway_instance + org_id + connection_ref + upstream_meeting_id + source_cycle_id`. `meeting_code` is display-only and must not merge rows across connections. Query failure keeps known meetings. `GET /api/meetings/{meetingId}` and its participants/recordings routes return stored rows; missing fields stay `not_provided` / `not_fetched`, never zero or success. Recording URLs are minted on authorized download and are not stored as long-lived signed links. This batch does not fetch arbitrary URLs.

B3 is local content: durable import runs keyed by stored `recordFileId`, never a client download URL. Source hash and content versions keep original/optimized transcript, Tencent minutes groups (`ai_ds_minutes` then `ai_minutes`, `ai_topic_minutes`, `ai_speaker_minutes`) and local revisions. Re-import updates source text and does not overwrite local edits. Tencent to-dos extracted from whitelist headings are source facts, not assigned OA tasks. Published `loudon84/anything-llm@codex/meeting-intelligence` `client.js` has no `getMeetingRecordFileDetails`; HTTP import records `IMPORT_CONTRACT_UNAVAILABLE` and does not claim a live recording download. Isolation `testAdapter.importRecordingContent` is the only import path that returns artifacts.

B4 is the OA workspace on `/meetings/:id/oa`: versioned drafts, stable `clientTaskId`, people search, and trusted employee mapping. Save draft is zero OA writes. Current identity is determined on the server; missing mapping still allows a valid draft and blocks formal sync with `OA_MAPPING_MISSING`. Controlled delegation is an explicit row; cross-user sync without it is denied. Secrets use native seal/open and are never echoed. Root is not a default employee.

B5 is the execution ledger: `meetingOaOperations` + steps + per-`clientTaskId` results + outbox lease (`leaseVersion` CAS, not a process lock). Pre-sync checks local account, meeting grant, `oaSync`, trusted creator/delegate, and draft fields, then freezes creator/payload in one transaction. Same `requestId` returns the original operation; a new `requestId` cannot open a second create intent for the same meeting + OA target. Writes run `createMeeting` → `uploadSummary` → `createTaskByMeeting`, persisting confirmed external ids before the next step. Timeout/lost response/`in_flight` crash is UNKNOWN and is not resent. GET is a pure read. OA non-idempotent writes must not use at-least-once jobs. Reconcile (`oaReconcile`) records evidence only. Recover (`oaResume`) is a separate execution-page command that keeps the frozen intent and continues only after `not_sent` evidence; the reconciler set does not include `oaResume`.

Do not call Agent, AnythingLLM, Casdoor, RAG, or a generic designer from this application. Live OA write HTTP (`server/utils/oa/*`, `oaMeeting.js`) is absent from `loudon84/anything-llm@codex/meeting-intelligence`; the HTTP adapter throws `OA_WRITE_CONTRACT_UNAVAILABLE` / `OA_TOKEN_CONTRACT_UNAVAILABLE` before fetch. People search HTTP follows `oaPeople.js` (`GET peopleUrl?fd_name=`), reading `meetingOaSettings.peopleUrl` at call time then env. Saving URLs without a new secret must not increment `credentialVersion`, because native open AAD is `[id, credentialVersion]`. `meetingOa.testAdapter` is isolation-only and must be labeled “本地测试数据，未调用真实OA” in the UI.
